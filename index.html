01 · The problem

One role.
A thousand applications.

Every CV is a claim.

Titles, keywords, years of experience. None of it shows what someone can actually build.

Praxis asks for the work.

One block of real evidence says more than a thousand claims.

02 · The attempt

90 minutes.
A real project.

An editor, a terminal and a live preview, in a cloud sandbox of their own. The server owns the clock.

Work saves
as they type.

Self-check tests run whenever they like. When time is up, the work is submitted for them.

Then the
hidden tests run.

In a fresh sandbox, on their source only. Nothing the candidate wrote can touch the grader.

    04 · Engines

    One core. Two engines.

    Praxis core runs clients, campaigns, invitations, release and audit. Assessment engines plug in through the Engine Contract.

    Project-based.

    A real project in a cloud IDE, in 14 stacks. Hidden tests, a skill map, a report PDF and the code as a zip.

    Prompt engineering.

    System and user prompts run on real models, graded on hidden cases for correctness, quality and cost against a reference prompt. Then run again for consistency.

    05 · Trust

    Signals,
    not verdicts.

    Time away from the tab, leaving full screen, pastes. Logged with context for a person to review.

    Reviewed,
    then released.

    Praxis reviews every result before the client sees it. Withdraw one and its share links stop working.

    Isolated by
    the database.

    Row-level security keeps each client's data apart, and every sensitive action is audited.
